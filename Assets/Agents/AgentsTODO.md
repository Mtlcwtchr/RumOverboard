## 1. Что это и зачем

**Graphiti** — фреймворк для построения и запроса *темпорального графа знаний* для AI-агентов.
В отличие от статической базы или плоского лога, он хранит **факты с временными окнами**
(когда факт стал истинным и когда был вытеснён новым), с полной провенанс-трассировкой к
исходным «эпизодам». Это даёт агенту долговременную память, которая **живёт между сессиями**
и корректно обновляется, когда решения меняются.

Подключается к агенту как **MCP-сервер** `graphiti-memory` (транспорт HTTP:
`http://localhost:8000/mcp/`).

### Для каких целей планируем использовать

| Тип знания (entity type) | Что храним в контексте RumOverboard |
|--------------------------|--------------------------------------|
| **Preference**  | Предпочтения пользователя: стиль кода, конвенции именования (`StylShip_*`, `RumOverboard/...` меню), язык общения, любимые подходы. |
| **Requirement** | Требования к геймплею и системам: нетворкинг на Fusion 2, буйность корабля, климб-система, поведение коллайдеров. |
| **Procedure**   | Повторяемые процедуры: как собирать gameplay-ship, как гонять авто-коллайдеры, шаги настройки океана/ветра, порядок сетапа мультиплеера. |
| **Decision**    | Архитектурные решения и **почему** они приняты (то, что не выводится из кода и git-истории). |
| Прочие встроенные | Location, Event, Person, Organization, Document, Topic, Object. |

> Цель: агент не переспрашивает одно и то же, помнит договорённости, соблюдает ранее принятые
> решения и предупреждает, когда новая задача им противоречит.

## 2. Установка сервера (делает человек, один раз)

Graphiti требует графовую БД и ключ LLM — это разворачивает пользователь, не агент.
Рекомендуемый способ — Docker Compose (поднимает FalkorDB + MCP-сервер):

```bash
# 1. Клонировать рядом с проектом (НЕ внутрь Assets/)
git clone https://github.com/getzep/graphiti.git
cd graphiti/mcp_server

# 2. Создать .env с ключом LLM
cat > .env <<'EOF'
OPENAI_API_KEY=sk-...
GRAPHITI_TELEMETRY_ENABLED=false
SEMAPHORE_LIMIT=10
EOF

# 3. Поднять сервер (FalkorDB + MCP на http://localhost:8000/mcp/)
docker compose up -d
```

Альтернатива без Docker:

```bash
cd graphiti/mcp_server
uv sync
uv run main.py --transport http --group-id rum-overboard
```

### Подключение к Claude Code

После запуска сервера создать в корне репозитория `.mcp.json`:

```json
{
  "mcpServers": {
    "graphiti-memory": {
      "type": "http",
      "url": "http://localhost:8000/mcp/"
    }
  }
}
```

Claude Code подхватит сервер автоматически. Проверить связь — инструментом `get_status`.

### Namespace

Вся память проекта живёт в группе **`rum-overboard`** (флаг `--group-id rum-overboard` при
запуске, либо параметр `group_id` в вызовах инструментов). Это изолирует граф RumOverboard
от других проектов на той же БД.

### Ключи и секреты

`OPENAI_API_KEY` и прочие ключи хранятся **только** в `.env` внутри `graphiti/mcp_server`
(вне этого репозитория). Никогда не коммить ключи в RumOverboard.

## 3. Инструменты MCP

| Инструмент | Назначение |
|-----------|------------|
| `add_memory` | Добавить эпизод в граф (text / JSON / message). Основной способ **записи** памяти. |
| `add_triplet` | Добавить один факт напрямую (сущность → факт → сущность), минуя извлечение. |
| `search_nodes` | Найти релевантные **сущности** (можно фильтровать по `entity_types`, `center_node_uuid`). |
| `search_memory_facts` | Найти релевантные **факты/связи** (фильтры по `edge_types`, датам `valid_at`/`invalid_at`). |
| `get_episodes` | Последние эпизоды группы. |
| `get_episode_entities` | Провенанс: какие сущности/факты создал конкретный эпизод. |
| `get_entity_edge` / `delete_entity_edge` | Получить / удалить ребро-факт по UUID. |
| `delete_episode` | Удалить эпизод и каскадно созданные им факты (при устаревании знания). |
| `build_communities` | Сгруппировать сущности в сообщества и построить сводки верхнего уровня. |
| `clear_graph` | Полностью очистить граф. **Только по явной просьбе пользователя.** |
| `get_status` | Проверить статус сервера и подключение к БД. |

## 4. Рабочий процесс агента (когда включим)

### В начале задачи — вспомнить
1. `search_nodes` по теме задачи → поднять **Preference / Requirement / Procedure**.
2. `search_memory_facts` по ключевым сущностям → поднять актуальные факты и их временные окна.
3. Учесть найденное **до** предложения решения. Найденные предпочтения и процедуры важнее
   дефолтных подходов; при конфликте — явно сказать об этом пользователю.

### По ходу работы — фиксировать
Как только всплывает новое знание — записать **сразу**, коротким самодостаточным эпизодом
через `add_memory`:
- пользователь выразил предпочтение или требование;
- принято архитектурное решение (и **почему**);
- выработана повторяемая процедура/шаги настройки;
- согласована конвенция (именование, структура, стиль).

Пиши по одному факту на эпизод, конкретно и без «воды». Относительные даты переводи в
абсолютные. Не откладывай запись на конец сессии.

### Что НЕ хранить
- То, что и так есть в коде, git-истории, `CLAUDE.md` или этом файле.
- Секреты, ключи, токены.
- Сиюминутный контекст одной сессии, который не понадобится в будущем.

### Обновление и устаревание
Graphiti сам версионирует факты по времени: при новом `add_memory` устаревший факт получает
`invalid_at`, а не удаляется. Явно удаляй (`delete_episode` / `delete_entity_edge`) только
заведомо ошибочные записи.

## 5. Примеры

Поиск перед задачей про коллайдеры:
```
search_nodes(query="ship collider setup preferences", entity_types=["Preference","Procedure"], group_id="rum-overboard")
search_memory_facts(query="StylShip hull colliders", group_id="rum-overboard")
```

Фиксация нового решения:
```
add_memory(
  name="Collider decomposition policy",
  episode_body="Для корпуса корабля (StylShip_Body/Prow) используется воксельная декомпозиция в набор боксов, а не один convex mesh — чтобы не перекрывать проходимый объём. Мачты — капсулы, паруса — тонкие боксы.",
  group_id="rum-overboard",
  source="text"
)
```
