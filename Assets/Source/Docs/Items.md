# Items — физические предметы, переноска, хранилища

GDD §3.4 / §26.3: инвентаря нет — только настоящие объекты, которые можно нести, бросить, потерять,
сломать. Игрок держит **один предмет в руках**; на корабле есть **хранилища** (сундук), куда предметы
кладутся физически (остаются сетевыми объектами, а не счётчиками). Host authority, как везде: хост
симулирует, клиенты видят реплицированное состояние.

## Управление

| Клавиша | Действие |
|---|---|
| `E` на предмет | взять (свободные руки, масса ≤ `CarryCapacity`; иначе подсказка «руки заняты» / «слишком тяжело») |
| `G` | положить (отпустить со скоростью несущего) |
| ЛКМ | бросить: скорость = `ThrowImpulse` / масса, максимум 12 м/с (бутылка летит, бочка — почти нет) |
| `Q` | использовать предмет в руках: бутылка — глоток, подзорная труба — смотреть (держать), ведро — выплеснуть (см. [Fire.md](Fire.md)) |
| `E` на сундук | с предметом — положить внутрь (если есть место), с пустыми руками — достать верхний |

С ношей нельзя лазать, вставать за штурвал и брать канат. Вес замедляет: скорость ×(1 → 0.5) при нагрузке
0 → 100% `CarryCapacity`; при нагрузке > 70% нельзя прыгать; движение с ношей тратит стамину
(`StaminaCarryCost` × нагрузка). Сбили с ног / ragdoll — предмет выпадает. Застрял предмет (> 1.5 м от рук
0.4 с) — выскальзывает.

**Ром только из бутылки:** `Q` без бутылки ничего не делает. Глоток тратит 1 `Sips` бутылки, даёт
опьянение `DrinkData.IntoxicationPerSip` и возвращает грог `DrinkData.GrogPerSip`.

## Данные (атрибуты профилей)

| Что | Где |
|---|---|
| `Mass` | масса тела (Rigidbody.mass) |
| `Integrity` | целостность; 0 → предмет ломается |
| `ImpactDamageThreshold`, `ImpactDamageScale` | урон от удара: (скорость удара − порог) × масштаб |
| флаг `Carriable` | можно взять в руки |
| флаг `Floating` | плавает (иначе тонет, с сопротивлением воды) |
| `Sips` (Resource) | заряды бутылки |
| `StorageSlots` | вместимость хранилища (реплицируется для подсказок) |
| Player: `CarryCapacity`, `ThrowImpulse`, `StaminaCarryCost` | сколько поднимает, сила броска, стамина за перенос |
| `IEntityData`: `DrinkData`, `SpyglassData`, `CompassData`, `StorageData`, `BreakableData` | что делает предмет / куда убирать / обломки |

Профили: Barrel, PowderBarrel, Board, Crate, GrogBottle, Spyglass, Compass (переносимые), Chest (хранилище).
Всё правится в F6 (атрибуты) и сохраняется в профиль.

**Скорость удара** = изменение скорости за два шага физики после начала контакта (гравитация вычтена),
но не больше скорости сближения перед контактом. Так работает и с упреждающим CCD, и при касании ребром,
а выталкивание из пересечения ударом не считается. Первую секунду после спавна урона нет.
Скорость «до контакта» берётся максимальной за последние 3 тика: упреждающий контакт иногда останавливает тело
чуть над поверхностью, и само касание приходит тиком позже уже на нулевой скорости (история сбрасывается при `Teleport`).

## Как устроено (`Assets/Source/Scripts/Gameplay/Items`)

| Файл | Что |
|---|---|
| `WorldItem.cs` | `NetworkBehaviour` предмета: `Holder`, `Container`, `Broken` (networked); масса из атрибута, плавучесть, урон от ударов, разрушение (обломки на каждом пире, despawn через 0.5 с), `Teleport` через NetworkRigidbody3D |
| `ItemInteractable.cs` | `Interactable` «взять»: доступность и подсказка по рукам и массе |
| `ItemStorage.cs` | хранилище: слоты (`NetworkArray<NetworkId>`), `TryStore`, `TakeLast` (LIFO), `SpillAll` при поломке |
| `StorageInteractable.cs` | `Interactable` «положить / достать» |
| `CrewCarry.cs` | хостовая логика рук: предмет ведётся к точке удержания `AttachMotor` (динамическое тело — цепляется за мир), столкновения с телом несущего отключены и возвращаются через 0.3 с после отпускания |
| `ItemRules.cs` | чистые правила: урон, нагрузка, замедление, бросок, прыжок, погружение |
| `ItemData.cs` | `DrinkData`, `SpyglassData`, `CompassData`, `StorageData` |
| `ItemCatalog.cs` | id → префаб (для спавнера и debug-окна) |
| `ItemSpawner.cs` | хост: расставляет предметы сцены после спавна корабля (палуба — от диаметральной линии на станции точки спавна №0, оси корабля / вода у борта / здесь), `AnchorToShip` — FixedJoint к корпусу |
| `HeldItemPresenter.cs` | локально: «В руках: …», зум подзорной трубы (`Q`), курс по компасу |
| `DebrisChunk.cs` | косметические обломки (без физики, работает и на клиентах) |
| `Debug/ItemsDebugWindow.cs` | **F8**: все предметы (масса, hp, кто держит, где лежит, заряды); хост — спавн из каталога, Give, −25%, Break, Refill, Despawn |

Изменения вне папки:
- **Машина состояний:** `PlayerState.Carrying` и `CarryingState`; совместимость с Grounded, InAir, Swimming и DrinkingRum. Лазание и штурвал запрещены с ношей. Питьё требует `ctx.CanDrink`.
- **`StateContext`:** `CarrySpeedFactor`, `CanDrink`, `SipIntoxication`.
- **`NetworkPlayer`:**
  - `PlayerNetState.Carried`;
  - `HandleItems` (взять, положить, бросить, хранилище, глоток);
  - `ApplyCarryToContext`;
  - API: `CarriedItem`, `CarryCapacity`, `DebugGiveItem`.
- **`Interactable`:** `InteractionKind.Item / Storage`. `InteractorInfo.Carried / CarryCapacity`; «руки свободны» теперь значит: нет ни каната, ни предмета.
- **`SimWorld`:** коллайдер ведёт к нескольким компонентам. Раньше `AttributesComponent` и `Interactable` одного предмета затирали друг друга.
- **`CrewStamina`:** расход на перенос.
- **`ControlHintsConfig`:** подсказки для `Carrying`; «Q — глоток рома» убрано из общего списка.

## Сцена, тесты

- **RumOverboard ▸ Items ▸ ★ Build Items Scene** → `Assets/Scenes/ItemsScene.unity`: бриг в штиль, предметы
  у точки спавна экипажа, сундук закреплён на корме, бочка/доска/бутылка в воде у борта; F8 открыто.
  Делает и контент (профили), префабы (если их нет; *Rebuild Item Prefabs* — перезаписать), каталог,
  перестраивает таблицу префабов Fusion (без неё `Runner.Spawn` не находит новые префабы).
- **Items ▸ Run Self-Test** — правила + целостность данных (профили, флаги, каталог без missing-скриптов).
- **Items ▸ Run Smoke (Play Mode)** — настоящий игрок на замороженном бриге, свежие тестовые предметы на
  свободной палубе: взять → глоток → в сундук → достать → положить → бросить → тяжёлая бочка (медленнее,
  без прыжка, стамина) → слишком тяжело → сундук с компасом ломается и рассыпается → удар ломает ящик →
  бочка плавает → без бутылки не пьётся.
- **Attributes ▸ Run Network Smoke** — на клиенте: бутылка в руках хостового игрока (Carrying), спрятана в
  сундуке, сундук сломан → бутылка снова видна.

## Ограничения / дальше

- Подзорная труба и компас — только локальная подача; карты пока нет (нет навигационных данных).
- Точка удержания — по курсу взгляда, без IK рук; предмет не поворачивается по тангажу.
- Хранилище — LIFO без UI выбора (минимум меню по GDD).
- Брошенная бутылка о стену обычно разбивается (порог 5 м/с, 4 hp) — так задумано, но стоит проверить на ощупь.
- Интеграция в gameplay-корабль ещё не делалась (по workflow — после стабилизации в ItemsScene).
- Огонь, порох, фонарь, ведро и бочка с водой — отдельная фича: [Fire.md](Fire.md). Её префабы собираются тем же
  сборщиком (`ItemsSetup.BuildPrefabsAndCatalog(specs, …)`, хук `ItemSpec.Decorate` для доп. компонентов).
